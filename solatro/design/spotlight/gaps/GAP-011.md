# GAP-011 — a section emptied by its own hooks: do `on_score` / `on_after_score` still fire?

- **Raised:** 2026-08-06, by the post-build code review.
- **Status: OPEN — behaviour unchanged pending the owner's answer.**

## The gap

`score_line`'s S8 re-evaluation (`Q22`=b, `Q23`=a) can come back empty: a spotlight hook discards
every card in the section (the unbounded-loop case `_spotlight_section`'s header names), or no card
in it is scorable (`HighCardHandler` returns `[]` for a section of stones). The code then does
`if result == null: return` — before `add_line_score`, `register_combo`, `_run_score_effects`
(the sole dispatcher of `on_score` per meld card and `on_after_score`) and `view.reset_meld`.

`Q244`=(a) rules only on the SCORE — *"the section scores NOTHING, there is no floor"* — and is
silent on the effect broadcast. Two readings:

- **(a) Skip the tail (current).** No result, no meld, nothing to fire on. Simple, and
  `view.reset_meld` never had an `animate_meld` to undo.
- **(b) Run the tail against a zero result.** A skill keyed on `on_after_score` ("after each scored
  line, do X") silently loses a trigger whenever a line empties itself — a combo-engine deck could
  care that the line was *attempted*, score or not.

### Answer

- **(a)** skip the tail on an emptied section (current behaviour; document at the null-return)
- **(b)** fire `on_after_score` (and which others?) with a zero/null result
- **(c)** other — describe.
