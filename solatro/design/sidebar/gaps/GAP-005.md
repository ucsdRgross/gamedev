# GAP-005 — the legal-cell highlight does not exist in the code, and nothing builds it
status: open
raised: during S15 (arming)
design: DESIGN.md version 10, nodes G12, E6, E16; answers Q24, Q124, Q129, Q280
severity: OWNER CALL (look), and a hole in the plan

**What the design says** — `Q24`=(a), carried forward as settled: *"legal cells are highlighted
while a card is held"*. `Q124`=(a) accepted the consequence: with a card armed at all times *"the
highlight is on for the whole show, and it is information the player wants continuously"*.
`Q129`=(c) makes it half of what tells the player something is armed: *"both, and they arrive
together, which is what makes the state legible"*. `Q280`=(a) leans on it again — the highlight
*"is literally the drop map"* for release-to-place. Chart node G12 states it outright.

**What the code does** — nothing. There is no legal-cell highlight anywhere in `solatro/`: not in
`PlayArea`, not on `CardVisual`, not on the cell slots. A CLICK pickup shows none either, so this
is not something arming lost — it was never built. `DESIGN.md` §1f lists `Q24`=(a) among rulings
"this design must obey", which reads as if it already existed; it does not.

**What it does not say** — what the mark IS. Every other mark in the board is spoken for:
`CardVisual.focused` is the focus glow (`Q249`: *"glow means selected"*), the lift is "picked up"
(`Q249` again), and `Q250`=(a) explicitly refused *"a third mark"* for the arm. A legal CELL is a
different object from a card, so its mark is a new visual with no precedent to copy: colour,
outline, fill, animation, and whether an OCCUPIED-but-legal cell (`Q121`) marks the same way.

**Why it blocks** — nothing is parked. S15 landed the arm, and the arm produces exactly the state a
click pickup produces, which is all `Q252`=b asks. But `TEST_PLAN.md` §11 claims every chart node
is covered by a test except `A1`-`A11`, `F1` and `M12`, and G12 has NO row in any section — so the
hole is invisible to the plan as written. S16 (`Q280`=a) and S21 both cite the highlight as if it
were on screen.

**Options I can see** — **(a)** build it in S16, where release-to-place needs the drop map anyway,
as a tint on each legal cell slot's own zone card, colour from `player_settings.gd` · **(b)** build
it now as its own small step before S16, so `Q129`=(c)'s "they arrive together" is true from the
first frame of a show · **(c)** retire `Q24`/`Q124`: with every empty cell in the committed grid
legal, a permanent highlight of most of the board says little, and `Q124`=(c) already offered that
reading · *my recommendation* (a), because the release path is the first thing that genuinely needs
a drop map and one step should own both
**Blast radius** — `UI/play_area.gd`'s cell slots, `Scripts/player_settings.gd` (one colour knob),
`TEST_PLAN.md` §6 (a new row) and §11; design nodes G12, E6, E16
**Meanwhile** — nothing is highlighted, exactly as today; arming is complete without it
