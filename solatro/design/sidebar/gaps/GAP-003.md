# GAP-003 — D11 says the map has no picture to convert through; the map lives in a picture
status: open
raised: during S4 (Phase 1 review)
design: DESIGN.md version 10, nodes D11, C13
severity: CONTRADICTION

**What the design says** — D11: *"The MAP uses the window fraction directly: it has no picture and
needs no conversion"*. PLAN §1.1: *"The MAP uses `container_px` directly with no conversion — it has
no picture."* PLAN §1.9 says the opposite in passing: the map's Fame/Lap/Luck *"sit in `map.tscn`'s
own `$UI` `CanvasLayer`, inside the map picture's viewport."*

**What the ANSWER says** — `Q247`=(a): *"it uses the window fraction directly, which is what the
number already is"*, asked as *"The map has no picture and no scale to convert through."* The
question's premise is what is wrong; the answer does not consider the case where it is false.
`Q27`=(d), owner note: *"center of screen for picture is center of remaining space not taken by
sidebar."*

**What it does not say** — `Levels/main.gd` attaches `map.tscn` as the `screen_root` of a
`WallPicture` (design size 1152×648) that covers the window, and the map's `Camera2D` has its own
player-driven zoom. A window-pixel offset applied to `Camera2D.offset` is multiplied by the
picture's cover scale and by the camera zoom before it reaches the screen, so "no conversion" only
centres the map at exactly 16:9 and at zoom 1.0: at 600×1000 the map's focus lands near the bottom
edge, and wheel-zooming the map walks it toward the right edge.

**Why it blocks** — the design contradicts the code (protocol item 3). It does NOT park the thread:
`Q27`'s intent is unambiguous and only one implementation satisfies it, so the code converts the
window offset through the picture's cover scale and the camera zoom, and this gap asks only for
D11's text to be corrected in the next design version.

**Options I can see** — **(a)** correct D11: the map converts exactly as the board does — window
px through the map picture's live scale, and through its own camera zoom — so the map's focus sits
at the centre of the remaining space at every window and zoom · **(b)** keep D11 literally and
accept the off-centre map away from 16:9 / zoom 1.0 · *my recommendation* (a)
**Blast radius** — plan step S4; design nodes D11, C13; PLAN §1.1's last line and §1.9's map note
**Meanwhile** — nothing parked; S4 implements (a) and records it in ASSUMPTIONS.md
