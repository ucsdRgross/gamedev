# GAP-011 — the legal-cell tint is wired, green and INVISIBLE: no card's art obeys `modulate`

status: ruled -- building
owner ruling: takes the recommendation, option (a): `outline.gdshader` multiplies by the vertex COLOR, so `modulate` draws for every card -- the legal-cell tint and the focus glow both reach the screen. The owner's words: "take recommendations for 11 and 12 gap".
raised: building `GAP-005`=a (the legal-cell highlight), at its by-eye gate
design: DESIGN.md version 10, nodes G12, E6, E16; `GAP-005`=a; touches `Q249`, `Q250`
severity: OWNER CALL (look), and it decides whether `GAP-005`=a is finished

**What the ruling says** — `GAP-005`=(a): *"a tint on each legal cell slot's own zone card, colour
from `player_settings.gd`"*. The only per-card colour channel a Godot CanvasItem has is
`modulate`, which `CardVisual.focused` already writes, so the tint was built as one derived
`modulate` combining the focus glow and the tint.

**What the code does** — the sweep, the knob, the combination and the test are all in and green:
`TestSidebar` 6.11 proves the tint marks exactly the cells `on_can_place_stack` accepts and moves
when a placement changes the answer. **The pixels do not change.** `Shaders/outline.gdshader`
ends `COLOR = out_col;` — it never multiplies by the incoming vertex COLOR, which is what carries
`modulate` — and that shader draws all five polygons of every card (face, rank, suit, type, stamp).

**Measured, not inferred** — `Tests/Visual/sidebar_snapshot.tscn` rendered three times: with the
shipped tint, with the tint set to WHITE, and with a deliberately loud `Color(4, 0, 0)` applied to
EVERY card. The 5×5 grid region of `card_lifted.png` is **byte-identical in all three** (PIL
`ImageChops.difference().getbbox()` over the grid rect returns `None`). The run printed
`SIDEBAR_SNAPSHOT card_lifted legal_cells=25 of=25 tint=(0.72, 1.35, 0.86, 1.0) held=1` in the same
frame, so the sweep and the property are right and the draw is where it is lost.

**The wider fact this uncovers** — `CardVisual.focused` writes `modulate` too, so **the focus glow
`Q249` calls "selected" cannot be drawing either**. `Tests/Visual/test_pixels.gd`'s
`test_effects_take_their_host_modulate` says the FX shaders were changed to multiply by COLOR
because *"shaders used to OVERWRITE COLOR, so a selected card lit up while its fire and balls did
not"* — the effects were fixed, the card's own shader was not.

**Options I can see** — **(a)** make `outline.gdshader` honour its host: `COLOR = out_col * COLOR;`.
One token, and it switches `modulate` on for EVERY card at once — the legal-cell tint AND the focus
glow, which no owner has seen on screen. `Q249` and `Q250`=(a) both assume the glow exists, so this
is the option that makes the shipped design true · **(b)** mark the cell through the shader's own
palette channel instead (a second ink/fill index on the zone card), leaving `modulate` dead and
`GAP-005`'s *"colour from `player_settings.gd`"* replaced by a palette entry · **(c)** draw the mark
outside the card: a panel or rect behind the legal cell's slot control, which keeps the colour knob
but stops being a tint ON the zone card · *my recommendation* (a), because it is the smallest change,
it is what every `modulate` writer in the project already assumes, and the glow it also restores is
a shipped design decision rather than a new one — but it changes how the whole board looks, which is
the owner's call and the reason this is a gap rather than a fix

**Blast radius** — (a): `Shaders/outline.gdshader`, one line, and every card on screen · (b):
`Cards/Types/type_grid_cell.gd` plus `CardOutline`, and `NAMES.md` loses the colour knob · (c):
`UI/play_area.gd`'s cell slots only
**Meanwhile** — the drop map exists in the data and in the test; nothing is on screen, which is
exactly the state `GAP-005` described before it was built

**As built** — the shader multiplies by a `varying v_modulate` that a two-line `vertex()` copies from
`COLOR`, not by the literal `COLOR = out_col * COLOR`: in `fragment()` the built-in `COLOR` is already
the vertex colour times `texture(TEXTURE, UV)`, and on the rim that texel is empty, so the literal
form erased the rim (three `PIXELS` rim checks and the rest-pose mask check went red). `test_outline`'s
pin narrowed from "no `vertex()`" to "`vertex()` never writes `VERTEX`", which is the rule skinning
needs. Correction to the measurement above: PIL's `ImageChops.difference(...).getbbox()` is alpha-only
on RGBA images, so it returned `None` for images whose colour differed; `.convert("RGB").getbbox()`
is the form that sees colour. The conclusion held anyway — at HEAD, `PIXELS` 6.12 measured the plain,
tinted and focused cards as the same mean colour.
