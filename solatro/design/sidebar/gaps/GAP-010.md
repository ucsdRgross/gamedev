# GAP-010 — hovering a map pack's preview card: what is "the way back to the pack"?
status: answered
raised: at the close review (S24), when building Q135=(b) after the S23 brief had misquoted it as (a)
design: DESIGN.md §4, node K9; answers Q135, Q133a, Q137
severity: OWNER CALL (not blocking; Q135=(a)'s behaviour ships meanwhile)
owner ruling: takes the recommendation, option (c) - "an explicit Back control in the description panel while a preview card is shown". The owner's words: "i will
take recommendation for all gaps". Build it; the work item is in HANDOFF_sidebar_gaps.md.

**What the design says** — `Q135`=(b): *"yes, and the sidebar switches to the card, with a way back
to the pack"*. Chart node K9: *"hovering one of those preview cards switches the sidebar to that
CARD, with a way back to the pack"*. The question's own note: *"the old panel did exactly (b) with
a `%CardInfo` label inside itself, which a single-surface sidebar cannot copy"*.

**What it does not say** — what "a way back" is. The single-surface sidebar makes that a real
choice: showing any entry through `HudContainer.show_description` → `DescriptionPanel.show_entry`
frees the panel's visual and grid slots, so switching to a preview card FREES the pack's grid —
including the card the pointer is on. "Leave the card to return" has no card left to leave.

**What the code does** — S23 built `Q135`=(a) from the brief's misquote: a preview card is inert
(`DescriptionPanel._make_still` makes every mounted control ignore the mouse and take no focus;
`MapHoverPanel.get_info` populates the grid with no inspect callback), and TestSidebar row S23.5
asserts that hovering one changes nothing. No input reaches a preview card today — mouse, pad or
touch. The panel resets its scroll on every new entry.

**Options I can see**
- **(a)** keep the grid under the card — the card's entry carries a link to its pack and the panel
  keeps the grid mounted (detached, not freed, the way a locked entry is kept) while the card's
  name, preview and body show above it; leaving the card returns the pack's text. Cost: the grid
  shifts under the pointer whenever the name row and body change height.
- **(b)** leave the sidebar — the card's entry replaces the pack; the pointer or pad focus leaving
  the sidebar, or cancel, brings the pack back (grid re-mounted, scroll restored).
- **(c)** an explicit Back control in the description panel while a preview card is shown.
- **(d)** hover the pack's map node again — no new control; works as soon as the switch exists.

Every option except (d) also needs the preview cards made reachable by mouse, pad and touch
(`Q137`=a, the multi-modal rule), and settles who keeps the pack's grid alive while the card shows.

*my recommendation* (c): it is the only way back a pad and a touch player can find without the
pointer, it keeps the grid from moving under the pointer, and the X already sets the panel's
precedent for a control that changes what the sidebar shows.

**Blast radius** — `UI/description_panel.gd` (`_make_still`, slot ownership, scroll memory),
`UI/hud_container.gd` (a pack-return path; navigation into the panel beyond the X),
`UI/map_hover_panel.gd` (`get_info` passes an inspect callback), `Levels/map.gd`, TestSidebar
S23.5 (re-aimed to the ruling), TEST_PLAN (a K9 row), NAMES.md.

**Origin** — the overseer's S23 brief quoted `Q135`=(a); answers.json holds (b). A script
