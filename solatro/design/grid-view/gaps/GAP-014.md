# GAP-014 — `BoardCoord` has no form for the legacy lower_zone, and a live test needs one

status: resolved
raised: 2026-08-27, during execution of S20b.2b (the coordinate migration)
design: grid-view DESIGN.md chart `M` (`M1`, `M3`); GAP-013's correction
severity: CONTRADICTION

## What the plan said

`slot_center_global(coord: BoardCoord)` was scoped to answer for exactly two cases: a grid cell,
and the Entrance (`coord.y == BoardCoord.ENTRANCE_ROW`). GAP-013's correction asserted this was
sufficient because *"every `slot_center_global` call in both files names zone 0, which is the
upper zone — the Entrance... `test_visual_layers`'s `below` derives from a fixture built in
`upper_zone`."*

## What the repo says — measured

That claim is false for one fixture. `Tests/UI/test_visual_layers.gd::_deal_until_stacked`
(`:1480-1500`) places every dealt card into **`lower_zone`** (`Board.place_card(g.state, card, 1,
col)`, zone argument `1`), not `upper_zone`. `test_the_reveal_opens_a_row_and_moves_the_slots_below_it`
(`:1080+`) then picks `below` from whichever zone's row 0 covers something first
(`pa.data_card.keys()`, no zone filter) — on this fixture that is **`lower_zone` (zone_x == 1)**,
not the Entrance.

The new `slot_center_global` has no way to express that coordinate: `BoardCoord` names a grid cell
or the Entrance, nothing else. The narrow `Vector3i -> BoardCoord` conversion this step adds at
test call sites (`BoardCoord.new(0, v.y, BoardCoord.ENTRANCE_ROW, v.z)`) hard-codes the Entrance
origin, so it silently reads the WRONG container's position for a `lower_zone` coordinate — measured
as a real geometry mismatch, not a rounding error (`pitch -14.0 -> 20.0, mode asks for 54.0`).

## Consequence

`Tests/UI/test_visual_layers.gd::test_the_reveal_opens_a_row_and_moves_the_slots_below_it` FAILS
two checks after this step (`S20b.2b`) lands:
- *"...leaving a row pitch of EXACTLY the mode's opening (GAP-009) — no stray separation"*
- *"...and the OPEN row re-derives to the mode's new opening — nothing was captured at spawn"*

Left failing, not patched — the fix is a scope decision (see below), not a local tweak.

## VERDICT — NOT A GAP. A fourth option existed and exactly one choice was defensible.

Filed in good faith by the implementer, and correctly: it stopped rather than inventing a
lower-zone coordinate. But the three options listed were not the whole set.

**(d) Make the test say which zone it measures, and stock that zone.** The selection loop took
*"any card at row 0"*, which its own comment admits *"lands on whichever zone the iteration reaches
first"* — the test was already zone-arbitrary, and that is a defect independent of this migration.
Filtering it to the Entrance (`v.x != 0` -> skip) makes it deterministic, and stocking BOTH zones in
`_deal_until_stacked` — rather than only the lower one — gives it a covered row it can name.

Why this is the only defensible choice:

- **(a) is forbidden by the design.** A third `slot_center_global` branch for `lower_zone` builds
  the coordinate form that `P1`/`P2` retire and `M8` says gets no shim.
- **(b) risks the fixture's stated purpose** — the paired shape at `:1482-1484` is deliberate.
  (d) keeps the pairing and adds depth, preserving the *"every column the same known depth"*
  property the fixture exists for.
- **(c) leaves the tree red**, and a step does not land red.

**Fixed**: both selection loops filter to the Entrance; `_deal_until_stacked` stocks both zones.
`ALL 43 SUITES: 3500 CHECKS PASSED`. The test is now stronger than before the migration — it
measures a named zone rather than whichever one the dictionary yielded.

## Options I can see

- **(a)** Extend the Entrance's boundary-conversion helpers (`slot_coord_v3` in both test files,
  the two `prop_layer.gd` sites) to read the legacy `Vector3i.x` (zone) instead of hard-coding it,
  and give `slot_center_global` a THIRD branch for `lower_zone` — cheap, but it is new scope this
  step's brief explicitly did not ask for, and it is exactly the code `S20b.4` is going to delete.
- **(b)** Fix the FIXTURE instead: make `_deal_until_stacked` build in `upper_zone`, matching what
  GAP-013 assumed. Smaller, but the comment at `:1482-1484` says the shape is deliberate ("paired to
  the Entrance column... the shape the play area's geometry is written against"), so this may
  silently break the thing that comment is protecting.
- **(c)** Leave it failing until `S20b.4` deletes the legacy zone rendering and rebuilds this
  fixture onto grids anyway (GAP-013's own stated plan for `test_visual_layers.gd`'s deeper
  coverage) — the two failing checks are re-derived then, not before.

**Blast radius** — `UI/play_area.gd` (`slot_center_global` and its two branches),
`Tests/UI/test_visual_layers.gd` (`_deal_until_stacked`, `slot_coord_v3`,
`test_the_reveal_opens_a_row_and_moves_the_slots_below_it`), `S20b.4`.
