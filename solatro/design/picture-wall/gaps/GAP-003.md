# GAP-003 — pinch-to-zoom is not generated on the platform this game is built on
status: resolved
outcome: answered
raised: 2026-08-15, during the post-chart engine verification pass
design: DESIGN.md version 3, nodes I8
severity: CONTRADICTION
resolution: |
  Answered (a) in chat, with an addition, verbatim: *"a, we add a touch gesture addon at later date
  for testing"*.

  So pinch ships hand-derived from `InputEventScreenTouch` and `InputEventScreenDrag` — two tracked
  touch ids and a distance delta — which works on every platform including Windows, where
  `InputEventMagnifyGesture` never fires. `Q119`=(a) stands as written; only its mechanism changes.

  A touch-gesture addon is a LATER, TESTING-ONLY concern — a way to exercise touch on a desktop box
  — and is deliberately not a shipping dependency. It does not enter this design, and nothing in
  v1 may be built assuming it exists.


**What the design says** — `Q119`=(a), charted as **I8**: *"Pinch out enters, pinch in goes to wall
view."* Charted as though the gesture simply arrives.

**What the ANSWER says** — `Q119`=(a) *"yes — pinch out on a picture enters it, pinch in goes to wall
view"*, no note. `Q118`=(a) went further: touch works fully, wall **and** every screen.

**What the docs say** —
[InputEventMagnifyGesture](https://docs.godotengine.org/en/stable/classes/class_inputeventmagnifygesture.html)
is generated by **macOS**' pinch gesture, and on **Android** only when
`input_devices/pointing/android/enable_pan_and_scale_gestures` is enabled. Windows is not listed.
[godot-proposals#4340](https://github.com/godotengine/godot-proposals/issues/4340) is the open
request for OS-agnostic gestures, and
[godot#39055](https://github.com/godotengine/godot/pull/39055) the unmerged PR for it — i.e. this is
a known gap in the engine, not a setting I missed.

This project's development and primary target is Windows (`platform: win32`, and
`export_presets.cfg`). So on the machine this is built and tested on, **the pinch event never
fires** — the feature would look unimplemented rather than broken.

**What it does not say** — whether the two-finger gesture should be derived by hand from
`InputEventScreenTouch` / `InputEventScreenDrag`, which is what every cross-platform Godot project
ends up doing, or whether pinch should simply be dropped in favour of the tap that `Q120`=(a)
already gives.

**Why it blocks** — observable behaviour differs by platform, and it is an owner call about scope:
hand-rolling multi-touch gesture recognition is a real subsystem, not a binding. It meets the
CONTRADICTION test — the design asserts a capability the engine does not provide here.

**Options I can see** — **(a)** derive pinch by hand from `InputEventScreenTouch` and `ScreenDrag` — two tracked touch ids and a distance delta, works on every platform, roughly forty lines · **(b)** drop pinch: `Q120`=(a) already makes a tap enter a picture and the on-screen Wall button already leaves it, so touch loses nothing it cannot do another way · **(c)** vendor an existing touch-gesture addon rather than write one, at the cost of a second vendored dependency and its rules · *my recommendation* (b) for v1, with (a) as the follow-up if touch becomes a shipping target

**Blast radius** — design node I8; §15 in full.

**Meanwhile** — parked: the pinch binding. Continued on: tap, the on-screen controls, and every
other input medium.
