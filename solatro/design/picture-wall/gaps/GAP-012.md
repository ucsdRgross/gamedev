# GAP-012 — the source-pause latch is frame-rate dependent and can be missed entirely
status: open
raised: 2026-08-16, during execution plan step S15 / the T13 soak
design: DESIGN.md version 5, nodes C9, D4; `Q72`=(a), `QR6`=(a); PLAN.md §1.6, §1.10
severity: CONTRADICTION

**What the design says** — `PLAN.md` §1.10: *"Pause boundary: source pauses the frame its outer edge
enters the view (`Q72`=a)"*. §1.6 requires that **exactly one screen root is `PROCESS_MODE_ALWAYS` at
a time**, and `TEST_PLAN.md` U3 and the phase-3 gate both assert it. The whole pause model
(`QR6`=(a)) rests on that invariant.

**What the ANSWER says** — `Q72`=(a) fixes *when* the pause happens, in geometric terms. Neither it
nor any other answer says how that instant is to be detected, and nothing anticipates the detection
failing.

**What it does not say** — **what happens when no frame is sampled inside the window.** Measured
against the real, unmodified `WallTransition` (`Tests/Visual/wall_transition_latch_timing_spike.gd`,
windowed, T13's own fixture):

- **The condition is TRANSIENT, not monotonic.** `source_frame_in_view` is true only across
  **[0.0048 s .. 0.0502 s]** of a 0.1 s transition — a ~45 ms window that opens *and closes again* at
  the 50 % mark, then stays false to landing. (`dest_visible` is [0.0427 s .. 0.1000 s] — it opens
  later but runs to completion, which is why the destination unpause never fails.)
- **One real transition produced `total_real_frames = 1`** for the whole 100 ms — the entire tween
  collapsed into a single callback, consistent with an ordinary first-frame spike: scene load, asset
  streaming, a GC pause, an alt-tab. That single frame landed *after* the window had closed:
  `source_paused_at_end = false`, `dest_unpaused_at_end = true`. Reproduced on a second independent
  run.
- **Reproduces on demand.** At `wall_transition_delay` 0.033 s it fails 2 of 3 trials; at **0.02 s
  and below it fails 3 of 3, every time.** ⚠ And it also fails **intermittently at 0.1 s**, the
  duration this run's own soak uses.

**Why it blocks** — triage test (3), and the failure is silent and load-bearing. When the latch is
missed the source screen **stays `ALWAYS`**, so two screens are live at once: the "frozen" screen
keeps running its `_process`, its animations and its game logic behind the picture the player is
looking at. That is the precise escape the entire pause model exists to close, and it produces no
error — only a wrong count that nothing in the shipping game checks.

⚠ **It is not confined to absurd durations.** A frame spike of ~50 ms swallows the window at the
default clock. Frame spikes are normal.

⚠ **The T13 soak cannot catch it**, because the soak was made deterministic by forcing a sample at
the plateau — correctly, since a flaky gate is worse than none. So the gate that exists to assert
"exactly one `ALWAYS` screen" is, for this defect, blind by construction. Any fix must come with a
test that does **not** force the sample.

**Options I can see** — **(a)** **compute the crossing time analytically at transition start**:
`sample_at()` is already a pure function of elapsed time, so scan or bisect once for the instant the
condition first holds and schedule the pause at exactly that time — frame-rate independent, and it
preserves `Q72`=(a)'s specified moment **exactly**, changing no observable behaviour; it must be
recomputed when S17 retargets mid-flight, and it needs a defined answer for geometry where the
condition never holds · **(b)** **make the latch sticky with a phase backstop**: pause on first
observation *or* at the end of the zoom-out phase, whichever comes first — trivial and robust, but
on a missed window the pause lands later than `Q72`=(a) specifies, so it changes observable timing ·
**(c)** **make the condition monotonic**: redefine it as "the source frame HAS entered the view"
rather than "is in the view", so once true it stays true — closest to the design's words, but still
frame-sampled, so a single-frame transition can still skip it entirely · *my recommendation*
**(a) with (b) as a mandatory backstop** — (a) alone is exactly right when a crossing exists, and (b)
guarantees the §1.6 invariant even when it does not; (c) alone does not fix the measured
one-frame case

**Blast radius** — `Scripts/Wall/wall_transition.gd`'s pause latch; `PLAN.md` §1.10's pause boundary;
`TEST_PLAN.md` T6, T13 and U3; step S15, and S17 if (a) is chosen, since retargeting invalidates a
precomputed crossing time. The destination unpause (`Q73`=c) is **not** affected — its window runs to
completion.

**Meanwhile** — parked: the latch's implementation. Continued on: everything else. Production code is
untouched and the defect is present in `ed61be0`; the forced-sample T13 stays, since a deterministic
gate is still the right gate.
