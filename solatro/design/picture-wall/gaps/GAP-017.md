# GAP-017 — M6 asks the tool for placeholder content; `CLAUDE.md` forbids mocks in tools
status: open
raised: 2026-08-17, during execution plan step S34 (the layout tool)
design: DESIGN.md version 5, node M6, `Q180`; `/CLAUDE.md` hard rule 5
severity: CONTRADICTION

**What the design says** — `M6` asks the layout tool to show **placeholder content** by default
rather than hosting the real screens.

**What the repo says** — `/CLAUDE.md`'s hard rules, which explicitly *"override defaults"*, rule 5:
**"No mocks in tools. A harness hosts the real scene and the real data; a stand-in cannot disagree
with what it models."** That is a repo-wide rule stated as non-negotiable, and it is the direct
opposite of M6.

**What it does not say** — which wins. This is triage test (3): the design contradicts the code's own
governing rules, not merely another document. `Q180`'s default sits with the repo rule rather than
with M6, which is why the conflict was not obvious until the tool was built.

**Why it matters beyond this step** — the rule exists for a specific reason, stated in it: *"a
stand-in cannot disagree with what it models."* A layout tool showing placeholder rectangles cannot
reveal that a real screen overflows its frame, renders at the wrong filter, or collides with the
overlay — and **this run has already found three defects of exactly that kind** that only appeared
once real content was on the wall: the overfill margin clipping the start menu's buttons, the
overlay covering Profile and Options, and the frame-corner behaviour at extreme sizes. A tool built
on placeholders would have shown none of them.

⚠ Against that, M6's motive is real too: the tool must open and re-pack instantly while an author
drags numbers, and hosting four live screens is heavier than drawing four rectangles.

**As shipped** — the tool hosts real scenes. This is **moot today**: all four registered pictures
have `scene == null` in production, so real-hosting and placeholder-hosting render identically. It
stops being moot the moment any picture gets a scene, which Phase 7's own wire-up makes likely.

**Options I can see** — **(a)** the repo rule wins, M6 is withdrawn — the tool always hosts the real
scene, so what an author tunes against is what ships; costs load time as pictures gain scenes, and
contradicts M6's text, which needs amending at source · **(b)** M6 wins for the tool only, with the
rule's exemption written down explicitly in `CLAUDE.md` rather than left implied — fast tool, but
re-opens the exact "the tool lied to the author" failure the rule was written to prevent ·
**(c)** both, as an author-facing toggle defaulting to real content — the author gets speed when
tuning geometry and truth when checking composition; one more control on a tool that already has
many, and the default decides which mistake is easy to make · *my recommendation* **(a)**, because
the rule is stated as overriding and this run's own defect history is evidence for it; but M6 was
answered deliberately and only the owner can withdraw it

**Blast radius** — `Tools/wall_editor.gd`'s content mode; `DESIGN.md` M6; `/CLAUDE.md` rule 5 if (b)
or (c) wins. No behaviour differs today, since every registered picture has a null scene.

**Meanwhile** — parked: the tool's content mode. Continued on: everything else. The tool ships
hosting real scenes, which is the safe default under either answer while all scenes are null.
