# GAP-041 — a show's score PEAKS three nodes in and then falls, so deck size cannot drive the goal

status: open
raised: refitting `goal_g0` / `goal_alpha` against the grid economy (Phase 9, `S39`)
design: `PLAN.md` §1.6 (the economy), §2 Phase 9; `RunManager.goal_for`; `QR5`, `Q322`, `Q129`
severity: THE GOAL CURVE'S ONLY GROWTH TERM HAS THE WRONG SIGN FOR MOST OF A RUN

## The measurement

`py solatro/Tools/scoring_sim.py --grid-goals --trials 800 --q 0.25`, par play, the measured
booster deck. The `median` column is what par play actually displays at End Show:

```
    N  ranks  grids  cells  placed   median
   20   1-5      1     25    20.0      9360     nodes 0-2   board 5 cells short of full
   25   1-13     1     25    25.0     60984     node  3     board EXACTLY full
   30   1-13     1     25    25.0     18360     nodes 6-8
   35   1-13     1     25    25.0     13311     nodes 9-11
   40   1-13     1     25    25.0     11088     node 12
```

**The score peaks at node 3 and ends the run at 0.16x that peak.** Two independent causes, both
measured in the shipped code rather than inferred:

1. **The board holds 25 cells for the whole run.** `SkillGridAllotment.target_grid_count` is
   `ceil(deck / grid_cards_per_unlock)` clamped to `[1, grid_max_count]`, and
   `grid_cards_per_unlock` ships at **52**. A run goes 20 -> 40 cards over 13 nodes, so it never
   reaches a second grid. `placed` is pinned at 25 from node 3 on: every booster card after the
   first pack is dealt into a show that cannot place it.
2. **Booster cards thin out the ranks that make melds.** `TypeBoosterBasic.get_possible_ranks()`
   returns ranks **1-13**, uniformly, from the first booster. The start deck (`deck14`) is ranks
   **1-5**. So each pack replaces dense, collision-heavy draws with sparse ones, and the lines that
   fill the same 25 cells stop forming sets. This is the difference between node 3 (60,984) and
   node 6 (18,360) — the board is equally full in both.

Under a product economy those two compound: `grid_score` is `row x col x special`, so losing melds
does not subtract from the score, it divides it.

## Why the phase's own deliverable cannot close this

`goal_for` is `goal_g0 * (N-hat / goal_n0) ^ goal_alpha * ...`. Its only growth term is deck size,
and past node 3 deck size is anti-correlated with score. Fitting two constants to that ladder:

```
  LEAST SQUARES: goal(N) = 9994.6 * (N/20)^2.94  R2(log)=0.6261  worst 86% out
  MINIMAX:       goal(N) = 10747.0 * (N/20)^2.95  worst 100% out
  BEATABLE:      goal(N) = 5376.0 * (N/20)^0.26  tightness 0.52 of the ladder
```

⚠ **MINIMAX IS THE PROOF, NOT LEAST SQUARES.** Minimax is the best any `(g0, alpha)` pair can do
against this ladder, and it is still **100% out** at some node. The shape moved; no pair of
constants recovers it.

The shipped constants are committed at the BEATABLE fit — the hardest curve that stays winnable at
every node — which comes out at `goal_alpha` **0.26**, i.e. very nearly flat. It validates at
**17.2% / 15.2% / 10.5%** run-win for skilled / par / average, which is a sane ladder. But a flat
`alpha` is the curve admitting it has no driver, not a balance choice.

For scale, the constants it replaces were fitted to the retired tableau and are wrong by orders of
magnitude in the other direction: `130 * (N/20)^4.2` asks **130** at node 0 against a median score
of **9,360**, and **2,389** at node 12 against **11,088**. Every goal in the game is currently
trivial.

## What is not the question

Not the sim's fidelity. The Python port is asserted against the engine by
`Tools/scoring_parity.gd` + `--parity`: 1200 engine-evaluated lines, **0 score mismatches**, and
exact agreement on `GameData.grid_score` (including every zero-bucket pattern) and
`GameData.combo_mult`.

Not the player model either. Skilled (every placement ideal), par (0.9) and average (0.7) land
within a few points of each other at every node, because board fill dominates placement quality.

## Options

**(a) Grow the board with the deck.** Drop `grid_cards_per_unlock` so a run actually unlocks its
second and third grid — at 25 it would reach 2 grids at node 3 and 3 grids at node 12, and cells
would track cards instead of capping them. Keeps `goal_for`'s shape and gives `alpha` a real driver
again. Costs: `grid_max_count` 3 becomes a hard ceiling the late run sits against, and three grids
is a screen-space and Entrance-commitment question the board work has not been asked.

**(b) Narrow what a booster adds.** Give `TypeBoosterBasic` a rank pool that tracks the deck it is
adding to rather than a flat 1-13, so packs deepen the deck's existing ranks instead of diluting
them. Fixes the decline without touching the board; leaves the capacity cap, so the score still
plateaus rather than falling.

**(c) Drive the goal off board capacity instead of deck size.** Replace `N-hat` with the cells the
run can actually fill (`grids * grid_width * grid_height`), leaving `goal_g0` / `goal_alpha`
otherwise as they are. The most honest fit to what was measured; it makes the goal curve depend on
a quantity no booster changes today, so it needs (a) to have anything to ramp on.

**(d) Accept a flat ladder and move difficulty elsewhere.** Ship `alpha` near 0 and let `difficulty`
and `lap_mult` carry the run's ramp. Cheapest, and already true of the committed constants — but it
concedes that crossing a booster node makes a run easier, not harder.

⚠ Both causes are independently sufficient. (a) alone leaves the booster dilution; (b) alone leaves
the 25-cell cap. Answering only one halves the problem.
