# GAP-002 — nothing defines what `step_x` does when it walks off the board
status: open
outcome: unanswered
raised: 2026-08-26, during execution plan step S1 (the BoardCoord type)
design: NAMES.md §1 (`BoardCoord.step_x`); PLAN.md §1.1, §1.3
severity: GAP

**What the design says** — `PLAN.md` §1.1 says `step_x` "crosses grid boundaries; derives
`grid` from the global column." §1.3 fixes each grid's width but says nothing about the
board's edges — what happens when the global column computed by `step_x` falls before column
0 of grid 0, or past the last column of the last grid.

**What the repo says** — the shipped `step_x` CLAMPS to the nearest legal column: stepping
past the left edge returns `(grid 0, x 0, y, h)` unchanged from `y`/`h`; stepping past the
right edge returns the last grid's last column. This is a provisional reading picked only to
avoid the previous implementation's dead-code bug (a negative global column fell through both
of `step_x`'s internal loops and returned a negative `x` on grid 0, an on-board-looking value
that was actually off-board) — it is not something any document decided.

**What it does not say** — which of several defensible readings is correct, or whether the
answer should differ between "walked off the left of the whole board" and "walked off the
right," or whether off-board should be representable at all given `BoardCoord.NOWHERE`
already exists as an off-board sentinel (TP-04).

**Why it matters** — callers built in S2/S3 (drag-drop, card movement across grids) need to
know whether an out-of-range `step_x` call is a silent clamp, a detectable sentinel, or a
value they must range-check themselves before trusting it. Each reading changes what calling
code has to do.

**Options I can see** — **(a)** return `BoardCoord.NOWHERE` — reuses the existing off-board
sentinel (TP-04) so "off board" has one representation everywhere, but callers that only
wanted to clamp a UI drag now have to special-case `NOWHERE` on a class of steps that isn't
really an error · **(b)** clamp to the nearest legal column — what the repo provisionally does
today; convenient for callers that don't want to think about edges (e.g. an arrow key held
past the edge), but silently discards the information that the step was out of range, which
could hide a real bug in a caller that expected multi-column movement to succeed · **(c)**
return the out-of-range coordinate (grid 0 or the last grid, with `x` outside `[0, width)`)
and let callers check — keeps all information and lets each caller decide clamp vs. reject vs.
treat-as-NOWHERE, but every caller now has to know to check, and an unchecked out-of-range
`x` looks like a legal coordinate to code that forgets to check · *item 1 of this step
implements (b) provisionally, pending this ruling*

**Blast radius** — `Scripts/board_coord.gd`'s `step_x`; `Tests/Engine/test_grid_board.gd`'s
off-board checks, which currently assert the clamp reading; every S2/S3 call site that steps a
`BoardCoord` past a board edge.

**Meanwhile** — parked: off-board policy. Continued on: on-board `step_x` arithmetic, which is
unaffected by this gap and fully tested.
