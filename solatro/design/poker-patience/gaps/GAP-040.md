# GAP-040 — `PlayContainer`'s height is authored fixed, so the play area is shorter than its picture

status: resolved
outcome: answered by the owner — **`PlayContainer`'s height tracks `game_picture_design_size().y`**,
  as its width already tracks the design width
raised: tracing why no buffer value could make `TP-140` pass after `GAP-036`
design: `GAP-036`, `GAP-031`, DESIGN.md §36 flowchart H (`H1`, `H3`)
severity: A MEASURED QUANTITY THAT LIES TO EVERYTHING DOWNSTREAM

## What was measured

```
game_picture_design_size()   (1495, 841)     the picture being laid out
pa.size, read live           (1495, 636)     the play area laying it out
                              ^ width EXACT   ^ height capped
```

`Levels/game_view.tscn`:
```
[node name="PlayContainer" ...]
anchor_right = 1.0        <- width stretches
offset_top = 3.0
offset_bottom = 639.0     <- height is a FIXED 636 px; there is NO anchor_bottom
```

**Width is anchored; height is a literal**, authored for the project's old ~648 px base window. So
the play area lays out an 841 px picture inside 636 px of height.

⚠ **`focused_board_zoom()` reads `size.y`.** Everything downstream of it — the focused zoom, and
therefore whether a focused grid isolates its neighbours — is computed against a height that is not
the picture's. **No value of `isolating_grid_buffer_px()` can fix `TP-140` while this stands**, which
is why the buffer re-derivation in `GAP-036` was necessary but not sufficient.

## OWNER RULING — track the picture height

`PlayContainer`'s height follows `game_picture_design_size().y`, exactly as its width already follows
the design width. **The asymmetry was an oversight, not a decision.**

⚠ **The play area becomes TALLER THAN THE ON-SCREEN WINDOW.** That is correct here — the picture is
rendered into a `SubViewport` the wall camera frames, and `H3` already establishes that the render
target is clamped while `size_2d_override` holds the layout at full size. **But verify by eye that
nothing on screen depended on the old 636.**

⚠ **The design size is not a constant** — it derives from settings through
`isolating_grid_buffer_px()`. A fixed authored offset cannot track it, so the height must be **driven
in code and re-applied when settings change**, the way the Entrance strip height already is. ⚠ Do not
replace one authored literal with another.

## Blast radius

`Levels/game_view.tscn` (`PlayContainer`), whatever re-applies its height on settings change,
`PlayArea.size`, `focused_board_zoom()`, `_board_window_local()`, `_apply_board_zoom_rect()`, the
Entrance strip reservation, and `TP-101`, `TP-105`, `TP-138`, `TP-139`, `TP-140`.
