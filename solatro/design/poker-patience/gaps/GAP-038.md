# GAP-038 — a row label's pitch must equal the card row's pitch; `SIZE_EXPAND_FILL` broke it

status: resolved
outcome: answered by the owner — **label + its buffer must total the card row separation**; the buffer
  comes OUT of that budget, never on top of it
raised: owner observation after `GAP-034` landed
design: DESIGN.md §19 (cross-grid alignment), `Q114`; supersedes `GAP-034`'s implementation
severity: A REGRESSION INTRODUCED BY THE PREVIOUS FIX

## OWNER RULING

> *"row score labels should have same separation or height as the card row separation height. I
> noticed that there appears to be buffer between the labels now that causes it to become misaligned.
> if using buffer, it should take part of the separation budget so that total combined label + buffer
> is same as card row separation"*

## ⚠ THIS IS A REGRESSION FROM `GAP-034`, NOT A PRE-EXISTING BUG

The two pitches are supposed to be identical, and by minimum size they are:
```
cards   depth_pitch = CardVisual.card_separation_play_custom + separation
labels  custom_minimum_size.y = card_separation_play_custom , stack separation = separation
```

**`GAP-034` added `label.size_flags_vertical = Control.SIZE_EXPAND_FILL`** so the label would have
vertical slack for bottom-aligned text. That makes each label absorb the stack's spare height instead
of staying at its pitch-matching minimum, so **the label pitch drifts from the card pitch and the
error accumulates down the stack** — which is the "buffer between the labels" the owner is seeing.

⚠ The word *"now"* in the owner's report is the tell: this appeared with `GAP-034`.

## The rule

```
label box height + its share of the separation  ==  card row separation (the depth pitch)
```
The buffer is **part of** the budget, never added to it.

## ⚠ THIS RECONCILES A CONFLICT `GAP-034` COULD NOT SEE

`GAP-034` needed the label's text to have vertical slack so it could bottom-align, and its first
attempt was measured INERT (`size.y - text_size.y = 0.000`) because `AutosizeLabel` grows the font
until the text exactly fills its box. Two ways to create slack:

- **grow the BOX** — what `GAP-034` did. Wins slack, **breaks pitch**. Rejected by this ruling.
- **shrink the TEXT** — keep the box at the pitch-matching height and stop the autosize filling it
  vertically. Wins slack, **preserves pitch.**

**The second is now the required answer.** ⚠ It was offered to the owner during `GAP-034` and declined
in favour of slack — *before either party knew growing the box would break the pitch.* The new
information is what changes the answer; this is not a reversal for its own sake.

⚠ **`AutosizeLabel` is where to do it**, not by fighting it: `_calculate_best_font_size()` fits
against `available_height := size.y`. The text must be constrained to less than the box.
⚠ **Whatever caps it must NOT be a bare literal** — a tunable literal in a source file is a defect.

## ⚠⚠ CLARIFIED INTENT — the LABEL SITS TOO HIGH ON THE CARD

The owner was asked what should actually look different, given the measurement showed the old labels
had **zero vertical slack** (`size.y - text_size.y = 0.000`; text exactly filled its 17 px box, so
`VERTICAL_ALIGNMENT_TOP` and `VERTICAL_ALIGNMENT_BOTTOM` render identically).

> **Owner: "the label sits too high on the card."**

**So the thing that must move is the label BAND'S POSITION within its row, not the text's alignment
inside the band.** The number reads against the card's upper area while the pip row is now at the
card's bottom.

⚠ **`GAP-034`'s whole premise was wrong, and the framing was mine.** "Same place, bottom-aligned
text" cannot express this: with no slack the alignment property is inert, and creating slack means
either a bigger box (which broke the pitch — this gap) or smaller text (which shrinks an already
12 px number). Neither moves the band. **`GAP-034` is withdrawn as implemented.**

## The order of work

1. **REVERT `GAP-034`** — both `size_flags_vertical = SIZE_EXPAND_FILL` and the
   `VERTICAL_ALIGNMENT_BOTTOM` line. That alone restores the pitch match this gap is about, since by
   minimum size the label pitch and the card pitch already agreed.
2. **MEASURE, then report — do not move anything yet.** For a scored row, the label band's global
   rect against its own card's global rect, specifically the card's BOTTOM edge where the pips sit.
   **Quantify "too high" before correcting it.**

⚠ **Do not guess the offset.** The geometry is not obvious: a card is ~110 px tall but the fan pitch
is only ~17 px, so in a stack each covered card shows only a ~17 px bottom strip — the same height as
the label's band. Whether the band should align with that visible strip, with the card's bottom edge,
or with the pip row inside it, is exactly what the measurement has to establish.

⚠ **Moving the band is a layout change and the accumulate trap applies**: *"`custom_minimum_size` IS
A FLOOR, NOT A CAP"* — a `VBoxContainer` is `max(own minimum, sum of children + separations)`, so
growing children past the stack's sum pushes a bottom-aligned gutter's rows upward and the error
ACCUMULATES. That is the owner-reported misalignment whose FIRST FIX WAS A FALSE GREEN.

## Blast radius

`UI/play_area.gd` (`_fill_label_stack`, `_create_label_stack`), `UI/autosize_label.gd`, the row
gutter's alignment with its own rows, and `GAP-034`'s committed implementation.
