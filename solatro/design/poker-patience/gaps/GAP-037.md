## The situation

Entrance clipping is solved by removing `clip_contents` from `EntranceStrip`, so its cards draw
outside the strip's rect instead of being cut. **That works for the strip. It does nothing for the
picture.**

`PlayArea.game_picture_design_size()` is a FIXED size — *"DERIVED FROM THE CAP AND THE DEFAULT GRID
SHAPE, NEVER FROM THE GRIDS A RUN HAS"*, and `Q166`=(a) deliberately rejected computing it at show
start. **It does not grow with Entrance depth.** So an Entrance column deep enough that its fanned
stack exceeds the picture's height renders **past the render target's edge** — genuinely off-screen,
not merely past the strip.

⚠ **Unclipping cannot fix this.** The failure mode is the render target, not the strip's clip flag.
The owner's guarantee — *"all entrance cards never get clipped"* — therefore holds only up to a
depth nobody has measured.

## ⚠ THE FIRST QUESTION IS NOT A DECISION — IT IS A MEASUREMENT

**Is that depth reachable in the shipped game?** Nobody has established this. `Q313` contemplates it
in its own wording — *"if entrance/input cards are somehow stacked with multiple cards as well
increasing in height"* — so it is at least anticipated by the design.

**Answer this before treating it as a gap.** If the rules cap Entrance depth below the limit, this
costs nothing today and should be recorded as unreachable rather than fixed — the same disposition
`GAP-028` took for `H24` under `Q7`'s cap.

## Options, IF it is reachable

- **(a) The picture's height grows with Entrance depth.** Honest, and it makes the guarantee true.
  ⚠ Contradicts `Q166`=(a) (*"`design_size` stays AUTHORED data ... NOT computed at show start"*) and
  ⚠ the render clamp was measured to BITE (6096 -> 4096), so it has a hard ceiling.
- **(b) The Entrance scrolls internally past a depth threshold** — its hidden bar
  (`vertical_scroll_mode = 3`) becomes visible, or the shared range the owner originally asked for is
  built after all. Preserves the fixed picture. ⚠ Reintroduces the second scrollbar the owner asked
  to remove, though only in the case where the content genuinely cannot fit.
- **(c) The game caps Entrance depth** so the case cannot arise, making the guarantee true by
  construction. Cheapest if the cap is natural; needs a rules decision, not a view one.

## Blast radius

`PlayArea.game_picture_design_size()`, `_entrance_strip_full_height()`, `EntranceVScroll`'s scroll
mode, the render clamp, and `Q166`=(a)'s standing.
