# GAP-042 — a prop that scores a card in the ENTRANCE banks into a bucket the score never reads

status: open
raised: the closing adversarial review of the grid run
design: `PLAN.md` §1.6 (the economy), §1.9 (the Entrance); `QR5`, `Q322`, `Q110`
severity: LATENT — unreachable in the shipped content, and silently loses score the moment it is reached

## What the code does

`PropScoreProps` (Knife) and `PropScoreTalents` (Hoop) both branch on where the card they are
passing sits:

```gdscript
if v.is_entrance():
    section = ScoringSection.of_line(g.state.upper_zone, true, v.h)     # LEGACY constructor
else:
    section = ScoringSection.of_line_at(g.state, v.grid, ScoringSection.LineKind.ROW, v.y, v.h)
```

`of_line` is the pre-grid bridge and leaves `section.grid == -1`. `Game.add_line_score` branches on
`section.grid >= 0`, so an Entrance section takes the legacy path and banks into
`state.scores_row_upper` and `state.row_total`.

**`GameData.live_total()` never reads either of those.** It is `board_total() * combo_mult()`, and
`board_total()` sums `grid_score()`, which reads only `scores_row`, `scores_col`, `scores_cell` and
`score_special`. So the points are added to a container that nothing displays and nothing scores,
and `has_met_goal()` never sees them. The combo still bumps: `register_combo()` runs before the
branch, so the multiplier moves while the points do not.

## Why it is LATENT and not a live bug

`spawn_props()` is called from exactly one place — `Game._run_score_effects`, over `result.meld` —
and a meld is the card list of a completed LINE. Lines only exist on grids. So a prop's origin
(`PipSuit._spawn_origin` → `grid_position_of`) is always a grid coordinate today, and
`row_slot_path` keeps the route inside that grid's row. **No shipped content can put a prop on the
Entrance row.**

⚠ **The API is built for it anyway, which is why this is worth deciding rather than deleting.**
`Game.row_slot_path` has an explicit `is_entrance()` branch that walks `upper_zone`,
`_stack_at_coord` resolves Entrance coordinates, and `prop_data.gd` documents mid-flight re-routes
onto a parallel row. The first effect that routes a prop through the Entrance — a re-router, an
Entrance-targeting suit, a rules card — fires this.

## Why this is a gap and not a defect

That the current behaviour is wrong is not in question. **What it should do instead is an owner
call about whether the Entrance participates in the economy at all**, and the two options differ
in observable score:

- **(a) Bank it into the committed grid's ROW bucket, at the Entrance's own row index.**
  `scores_row` is keyed `Vector3i(grid, index, height)` and `-1` is a legal index, so this is a
  one-line change to the existing branch. The Entrance then feeds the row term, and — because
  `grid_score` is a PRODUCT — an Entrance hit can be worth far more than its face value, since it
  may be what opens a grid's row bucket from zero.
- **(b) Score nothing for a card in the Entrance.** Return early instead of banking. The Entrance
  is a waiting area, not part of the board, and the economy is defined over grid lines; a card that
  has not been committed to a cell has no line to score into. ⚠ Then `register_combo` must move
  behind the same guard, or the multiplier still moves for a hit that pays nothing.
- **(c) Give the Entrance its own bucket**, outside the three-bucket product, added to
  `board_total` directly. Keeps the reward without letting a waiting card multiply a grid's score.

⚠ **Do not resolve this by deleting the Entrance branch and letting it fall through to
`of_line_at`.** `v.y` is `-1` there and `v.grid` is whichever grid the Entrance is attached to, so
the section would collect a row that does not exist and score an empty card list — the same loss,
with the branch that documented it gone.

## What was done instead

Nothing. The thread is parked and the behaviour is unchanged, per the gap protocol. The bug is
recorded in `todo.md` alongside this file so it cannot be rediscovered from scratch.
