# GAP-042 — a prop that scores a card in the ENTRANCE banks into a bucket the score never reads

status: ANSWERED — the owner ruled, and the ruling goes further than this gap asked
raised: the closing adversarial review of the grid run
design: `PLAN.md` §1.6 (the economy), §1.9 (the Entrance); `QR5`, `Q322`, `Q110`, `Q28`
severity: LATENT — unreachable in the shipped content, and silently loses score the moment it is reached

## THE ANSWER

Owner, verbatim:

> *"entrance should be considered part of grid. by default it should score into its own row label,
> which goes into its own row bucket as if grid is 5x6. column based score should go into shared col
> score labels between entrance and grid. height labels should go below the entrance row to prevent
> overlap with column scores in same area, since currently height scoring stacks on top of stacks.
> right above entrance is the col scores though, so we use the empty area below entrance for entrance
> height scores. special scores go into the shared single bucket for everything."*

Three follow-ups settled the parts that ruling does not reach.

**Does a COLUMN now need all six cells to complete?** — **No.** A column completes on its 5 grid
cells exactly as today; an Entrance card in column *i* banks into column *i*'s shared bucket and
label. No completion rule moves.

**Do diagonals run through the Entrance row?** Owner, verbatim:

> *"no by default, but a future effect could allow it, such as one that includes the entrance row as
> part of the grid so its now 5x6"*

**Does the Entrance row score as a row automatically on every refill?** Owner, verbatim:

> *"intended if effect allows it, no by default"*

## What that means, stated once

⚠ **THIS IS ABOUT WHERE ENTRANCE SCORES BANK, NOT ABOUT DETECTING LINES IN THE ENTRANCE.** Read as
"the Entrance is now a scoring row", it would hand the player a free scored hand on every refill —
the Entrance refills to all five slots, so a row-completion rule would fire every cycle with the
hand decided by the draw. Both follow-ups rule that out **by default**.

**By default, the Entrance detects NOTHING new:**

- No Entrance ROW completion. A full Entrance is not a scored line.
- No diagonals through the Entrance row.
- Columns complete at 5 grid cells, unchanged.

**What DOES change is the destination of a score already attributed to an Entrance card** — which is
exactly what this gap was about:

| Score shaped like | Banks into |
|---|---|
| a ROW | the Entrance's **own** row bucket and row label, as if the grid were 5×6 |
| a COLUMN | that column's **shared** bucket and label — the same one the grid column uses |
| a vertical stack | that cell's bucket, which folds into **special** |
| anything special | the one **shared** special bucket |

**And a future effect may promote the Entrance into the grid**, making it genuinely 5×6 — at which
point row completion and diagonals through it both switch on. The geometry must therefore be
*extensible*, not hard-wired to exclude row 5 forever.

## Layout

Height score labels for Entrance stacks go **below** the Entrance row. Above it is the column-score
strip, and height labels currently render above their stack, so an Entrance stack's label would
collide with the column scores. The empty band under the Entrance is where they go.

## ⚠ Two things the implementation has to fix on the way

- **`GameData._scan_grid_positions` hard-codes the Entrance to GRID 0** — it builds
  `BoardCoord.new(0, c, ENTRANCE_ROW, h)` regardless of `committed_grid`. Harmless while nothing
  reads an Entrance coordinate's grid; wrong the moment a bank keyed on `(grid, index, height)`
  reads it, which is what this ruling introduces.
- **`Q28`=b said slot *i* aligns with column *i* "visually only".** Shared column buckets make that
  alignment MECHANICAL. This ruling supersedes that half of `Q28`; the other half — a card from any
  slot may still be placed in any column — is untouched.

## The defect this gap was filed for

`PropScoreProps` (Knife) and `PropScoreTalents` (Hoop) build an Entrance section with the legacy
`ScoringSection.of_line`, which leaves `section.grid == -1`, so `Game.add_line_score` takes the
legacy branch into `state.scores_row_upper` / `state.row_total` — neither of which
`GameData.live_total()` reads. The points vanish; the combo still bumps, because `register_combo()`
runs before the branch.

It is LATENT: `spawn_props()` is called only from `Game._run_score_effects` over `result.meld`, and
a meld is always a grid line, so no shipped content can put a prop on the Entrance row. But
`Game.row_slot_path` has an explicit Entrance branch built for exactly that, so the first
re-router fires it.

⚠ **Do not fix it by deleting the Entrance branch and falling through to `of_line_at`.** `v.y` is
`-1` there, so the section would collect a row that does not exist and score an empty card list —
the same loss, with the branch that documented it gone.
