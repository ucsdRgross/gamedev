# GAP-043 — effects cannot feed the combo without a reset rule, and the grid game has none

status: OPEN — needs an owner ruling before any code moves
raised: the second closing phase, reviewing the ~272 commits the first close had skipped
design: `DESIGN.md` D11 (`Q323`=b), D13; `PLAN.md` §S14, §1.6
severity: LIVE — every show is scored with a smaller multiplier than D11 specifies

## THE DEFECT, WHICH IS NOT IN DOUBT

`Levels/game.gd:231` — `if feeds_combo and _act_cancellable: register_combo(mod.combo_key(function))`.

`_act_cancellable` is written in exactly two places, `game.gd:452` and `:455`, both inside
`_perform_next()`, bracketing the `on_next` window. **`place_card_in_grid` never sets it**, and a
placement is the grid game's only scoring action. `CardEnvironment.run_all_mods` is the only dispatch
passing `feeds_combo = true` (`card_environment.gd:113,120`), and the placement cascade calls it four
times: `on_board_mutated` (`game.gd:689`), `on_card_placed` (`:770`), `on_score` (`:1145`),
`on_after_score` (`:1146`). The base `CardModifier.combo_key` returns a non-empty script path, so
those mods would register if the gate let them.

`DESIGN.md` D11 is *"melds and effects both feed combo on the same terms"*. **They do not.** Only the
meld class (`game.gd:989`) and three effects that self-register at their own seam
(`prop_score_props.gd:16`, `prop_score_talents.gd:16`, `status_juggling.gd:80`) reach the multiplier.

⚠ **THOSE THREE CARRY A STALE COMMENT** — *"also reaches the dispatch hook via run_all_mods;
register_combo is idempotent, so the double registration is harmless."* On the placement path the
dispatch hook does not reach it, so those self-registrations are LOAD-BEARING.

⚠ **ORIGIN `b36c5336`, PRE-GRID.** `_act_cancellable` meant "an act is resolving" when the act WAS
the `on_next` cycle. The scoring action moved to placement; the flag did not.

## ⚠ WHY THE OBVIOUS FIX IS WRONG, AND WHY THIS IS A GAP RATHER THAN A DEFECT

Deleting the gate looks like a one-line fix. **It would break scoring outright**, because the grid
game has no combo reset at all:

- **`combo_repeats` is NEVER cleared. Anywhere.** Grep every production write: `game.gd:210`
  (`+= 1`) is the only one. Nothing zeroes it.
- **`combo_classes` is cleared in exactly one place — `GameData.apply_act_score():94` — which is DEAD
  PRODUCTION CODE.** Its only callers are tests (see the handoff's Open bugs). So in the shipped grid
  game nothing clears it either.
- **The multiplier is uncapped.** `combo_mult() = 1.0 + combo_unique_step * classes +
  combo_repeat_step * repeats`, and `player_settings.gd` ships `combo_unique_step = 1.0`,
  `combo_repeat_step = 0.5`, `combo_cap = 0.0` — and `combo_cap` of 0 means NO CAP
  (`game_data.gd:80`).

So the gate is currently **the only thing bounding combo growth from mod dispatch**. Open it and every
mod firing on every placement adds a class or a repeat, at +0.5 each, for the length of a show, with
no ceiling. `live_total() = board_total() * combo_mult()`, so the score would run away.

**D11 therefore cannot be delivered by removing the gate. It needs a reset rule, and D13 —
*"HUD is always live: no act, no banking moment"* — deliberately removed the event that used to
provide one.** That is a decision the design does not cover: two or more defensible answers, observably
different, expensive to reverse once content is tuned against it. Hence a gap, not a defect.

## OPTIONS

**(a) Leave the gate. Amend D11 instead.** Effects feed combo only in the `on_next` window; melds feed
it on placement. Costs nothing, changes no balance, and makes the code honest — but it abandons a
ruling the owner already gave, and the three self-registering effects stay inconsistent with every
other effect.

**(b) Open the gate; reset combo per PLACEMENT.** Each placement becomes the combo window, replacing
the retired act. Big single-placement multipliers, back to x1 each time. Closest to the pre-grid feel.

**(c) Open the gate; combo accumulates for the whole SHOW, with `combo_cap` set.** The multiplier
becomes an escalating reward for a long show, bounded by the cap. Fits D13's "no banking moment"
most naturally, but the cap value is new tuning and the curve interacts with `GAP-041`.

**(d) Open the gate; reset per MELD.** `_begin_meld()` (`game.gd:145`) already exists and already
brackets exactly one scored line, so the machinery is there. One placement completing a row, a column
and two diagonals would score four independent combos.

⚠ **CHECK FOR A FIFTH OPTION FIRST.** Six gaps in this stream were answered with an option nobody
listed. The real question underneath is *what is the unit the combo measures* now that the act is
gone — and the owner may name a unit none of these four assume.

## WHAT MUST NOT HAPPEN

Do not open the gate without answering the reset question in the same change. A run that ships (b),
(c) or (d) half-done produces an uncapped multiplier and every playtest number afterwards is garbage.
