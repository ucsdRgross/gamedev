# GAP-018 — `grid_swipe_threshold_mm`'s default is dead against its own clamp

status: open
outcome: —
raised: during the Phase 6 defect pass on `S29` (the one-finger swipe)
design: DESIGN.md `Q190` and its settings table row; NAMES.md §6 (`grid_swipe_threshold_mm`,
`PlayArea._swipe_threshold_px()`)
severity: A KNOB THAT DOES NOTHING AT ITS OWN DEFAULT

## The measurement

`PlayArea._swipe_threshold_px()` converts the knob through `WallInput.mm_to_px` and clamps the
result to `[wall_touch_target_min_px, wall_touch_target_max_px]` = `[32, 96]` px.

At the registered default of **8.0 mm** and a nominal **96 DPI**, the conversion is
`8.0 / 25.4 * 96 = 30.2 px` — **below the floor**. The clamp returns 32 px. Turning the knob down
changes nothing at all, and turning it up changes nothing until it passes ~8.47 mm.

The knob is live above that point, so it is not simply unwired: an assertion that the millimetre
setting drives the px result now exists in `TP-109` and passes. What no test can assert without
choosing a side is that the DEFAULT is a converted millimetre reading rather than a clamp bound.

## Why this is a decision, not a defect

The design fixes BOTH numbers, and they disagree:

- `Q190`=(a) — *"a `PlayerSettings` knob in millimetres, converted through the existing
  `WallInput.mm_to_px` and **clamped like the touch-target size**"*. Read as "the same bounds", the
  clamp as built is exactly what was asked for.
- DESIGN.md's settings table and NAMES.md §6 both register the default as **8**.

`Q190` is answered; nothing here is an unanswered question. What is unfixed is which of the two
answers gives way, and the two options are observably different:

- **(a) The DEFAULT is wrong.** Raise `grid_swipe_threshold_mm` above the floor — 9.0 mm is the
  touch-target default and is the same physical size the wall already uses for a finger — so the
  knob's default sits inside its own range. Observable: the default threshold becomes a converted
  millimetre reading (34 px at 96 DPI) and moves with the screen's DPI, as `Q190`'s "the same
  physical swipe means the same thing on every screen" asks. The touch-target bounds keep
  protecting against a wild DPI reading.
- **(b) The CLAMP is wrong.** The touch-target bounds size a THING TO HIT; a swipe threshold is a
  DISTANCE TO TRAVEL, and 32 px is a large fraction of a small screen. Give the threshold its own
  bounds. Observable: the 8 mm default is honoured at every sane DPI, and two new settings enter
  the registry — which NAMES.md does not have, so this option cannot be taken without registering
  them.

Not changed pending the ruling: the clamp and the default both stand as they are.
