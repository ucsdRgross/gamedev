# GAP-034 — row score labels are top-aligned while the pip row sits at the card's bottom

status: resolved
outcome: answered by the owner — **row score labels get BOTTOM-ALIGNED TEXT, in place**; nothing moves
raised: owner instruction after the pip row moved to the bottom of the card
design: DESIGN.md §19 (cross-grid alignment), `Q114`; ⚠ NOT `Q309`/`E17` — see scope below
severity: A LABEL ALIGNED TO THE WRONG EDGE OF THE THING IT LABELS

## OWNER RULING

> *"score labels should be aligned with bottom of card instead of top of card now that pip row is on
> bottom of card"*

Scoped by the owner to the **ROW SCORE LABELS**, and to **text alignment only**:

- The labels **stay exactly where they are.** Nothing is repositioned; no layout moves.
- Only each label's own vertical text alignment changes, so its text sits flush with the card's
  BOTTOM edge rather than its top — level with the pip row it reads against.

## ⚠ SCOPE — what this does NOT touch

**`Q309` and `E17` are NOT affected and must not be edited.** They govern the CELL/HEIGHT score
labels in `_sync_cell_score_labels()`, which are positioned by arithmetic in their own layer riding
`slot_center_global`. Those keep sitting ABOVE the topmost card, exactly as
`Q309`=(a) specifies — *"above the topmost card of the stack, so the label rises as the stack
grows"*. The owner considered moving them and chose not to.

⚠ This matters because `Q111` was RETIRED to move the height label from BELOW a stack to ABOVE it.
**Do not read this ruling as reviving `Q111`.** It is a text-alignment change to a different set of
labels.

## Where the work is

`UI/play_area.gd`: the `RowLabels` `VBoxContainer` (`:2057-2061`, already
`BoxContainer.ALIGNMENT_END`) and `_bind_grid_score_labels()` (`:2129`), which fills the label stacks
from `state.scores_row` via `_fit_children` / `_fill_label_stack` and `_create_label_stack`.

⚠ **The CONTAINER is already bottom-aligned (`ALIGNMENT_END`); what is asked for is the TEXT's
alignment INSIDE each label.** Do not "fix" this by changing the container's alignment — it is
already correct and the floor rule depends on it (*"the floor comes from `TopLevelVBox` via
`ALIGNMENT_END`"*).

## ⚠ Row-label alignment has burned this stream twice — verify BY EYE

- *"Row labels line up with their own rows"* was an **owner-reported bug**, and **the FIRST fix was a
  false green.**
- **Height labels were 47 px out in focused mode**, because a site adding a measured global to a
  local size was not zoom-aware.

So: **a green suite is not evidence here.** Render it and look. ⚠ And any arithmetic touching these
labels must obey the standing rule — *"EVERY SITE THAT ADDS A MEASURED GLOBAL TO A LOCAL SIZE MUST BE
ZOOM-AWARE"*; label sizes are local magnitudes and must be taken into screen pixels by `board_zoom`.

## Blast radius

`UI/play_area.gd` (`_bind_grid_score_labels`, `_create_label_stack`, `_fill_label_stack`, the
`RowLabels` construction), the `BigNumberLabel` vertical alignment, and any check asserting a row
label's position or extent.
