**Invocation shape (still current; only the `--headless` flag is superseded — see the top of this memory):**
`"<binary>" --path . res://Tests/all_tests.tscn` with **NO `--quit-after`**. `all_tests.gd` calls `get_tree().quit(failure_count)` the instant every suite finishes, so it self-terminates (~6 s back when it was 17 suites headless; ~60 s windowed today). Run it as ONE background command, wait for the process to exit, then grep the output file for the summary line (`CHECKS PASSED` vs `FAILED`).

**Pitfalls that cost me many retries (avoid):**
- **Do NOT pass `--quit-after <ms>` to force-quit a scene.** It keeps the process ALIVE for the full duration regardless of when tests finish — an 8-check suite with `--quit-after 60000` idles a full 60s. This is what made runs look "slow/hung." Individual test `.tscn`s do NOT self-quit (only `all_tests.gd` does), so just run `all_tests.tscn` instead of a lone suite.
- **Never run multiple `godot --headless` instances concurrently** — they starve each other (Intel UHD), so each gets cut off / looks hung. One at a time.
- **Scene filename ≠ script name.** e.g. `test_scoring.gd`'s scene is `test_score.tscn`. Glob `Tests/**/<name>.tscn` before invoking a single suite (or just run all_tests).
- After adding a new `class_name`, the `.godot/` global class cache is stale → "Could not find type X" / "Could not find base class SolatroTest". Delete `.godot/` and run `--headless --path . --import` once (ignore the unrelated `yard` addon editor error), then run tests.
- Warnings are errors here: type every `for` loop var (`for x: T in ...`), and class-ref arrays inside functions must be `var ... : Array[GDScript]` not `const` (not a constant expression).

**Never read the full `all_tests.gd` (all_tests.tscn) output directly — it is too much** (user, 2026-07-11). The runner ends with one of two summary lines: `print("======== ALL %d SUITES: %d CHECKS PASSED ========")` on success vs `printerr("======== ALL %d SUITES: %d passed, %d FAILED (%d behavior, %d implementation) ========")` on failure. To decide pass/fail, only detect WHICH of those two lines/paths was taken (e.g. grep for `FAILED` or `CHECKS PASSED`), not the whole log. Read the full output directly ONLY when it failed, to locate the failing suite/check.
